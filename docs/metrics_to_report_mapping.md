# Metrics-to-Report Mapping

Every value in the PDF comes from the stored analysis summary (`AnalysisSummary`)
or the run metadata (`RunMetadata`). `report/view_model.py` only formats and
translates; it never recomputes analysis values. Most values come from the
summary's `diagnosis` block (`d` below; contract in
`summary/diagnosis_contracts.py`).

## Page 1 (owner)

| Report element | Source | Format |
|---|---|---|
| Car, tires, date | `metadata.car` name and type, `metadata.analysis_settings` tire size, `start_time_utc` in the browser-reported time zone, else with `recorded_utc_offset_seconds`; "not verified (the Pi clock was not set)" when `metadata.start_time_unverified` (also for runs from older releases or an earlier boot, which can never be corrected) | `225/45R17`; local time with UTC offset |
| Speeds driven, duration, sensors | `speed_stats.min_kmh`/`max_kmh`, `duration_s`, `sensor_count_used` | `50–118 km/h` ("no live speed recorded" without a speed range, in the PDF header and test conditions and History's no-fault card), `m:ss` |
| Verdict headline | `d.verdict`, `d.source`, `d.zone` | "Likely cause: …", "Not enough evidence to name a cause", "Vibration found, but no checked cause explains it" (`no_fault` with `d.unexplained_vibration`), "No significant vibration found", or "No result: this run could not check for a cause" (`no_fault` with no `d.source_checks` entry `candidate`/`ruled_out`/`ruled_out_estimated`: the next step asks for live GPS/OBD speed after a hand-typed speed, for a GPS fix when the live speed was missing (`speed_missing`), or for the tire size, and the shop request says it neither indicates nor rules out a repair); brakes read "brake judder from the brake discs on the front/rear axle" (unlocated: "felt strongest at …") |
| Confidence | `d.confidence_level` | Level word + action meaning; never a percentage |
| Plain description | `d.order_code`, `d.frequency_hz`, `d.reference_speed_kmh`, the top two `d.location_amplitudes` (ratio), `d.speed_min_kmh`/`speed_max_kmh`, `d.speed_dependence` | One sentence, plus "It follows road/engine speed: …" after a guided coast-down, or "only while braking" for brakes |
| Weak reasons | `d.weak_reasons` (`intermittent`: `d.presence_ratio`, the share of the moving drive in which the order was there, is under half; `loose_mount`: strongest at a sensor the loose-mount check flagged) | Plain sentences, no percentages; `single_sensor` / `single_wheel_sensor` / `loose_mount` is also appended to a fault's description, and a one-row `d.location_amplitudes` reads "measured at the …, the only sensor" |
| No-fault sentence | `d.source_checks[]`, `warnings[]` (`sensor_loose_mount`) | "Nothing stood out in the checks this run could make: wheels/tires, driveline and engine (top gear only)." (a `faint_only` check reads "wheels/tires (found only faintly, at a level a healthy car also has)") plus "Not checked, so not shown to be fine: …" for `not_testable` sources; a run that could check nothing says so; a loose sensor adds "The rear-left wheel sensor may be loosely mounted; check its mount and record again, because a loose sensor can hide a fault." |
| Covered / not covered (no fault) | Covered: `speed_stats`, `phase_info.phase_pcts`, `d.location_amplitudes` locations (with no speed range, "No live speed was recorded …" and the locations; with a speed range but no driving phase, the speeds and locations without phases). Not covered: `d.source_checks[]` (`not_testable` and `ruled_out_estimated`, each with its fix; brakes `no_braking` asks for a few firm stops from about 100 km/h, because coasting does not count, and an EV's or PHEV's `regen_braking` for the guided test's firm stops with regeneration at its lowest, or firm stops on the brake pedal, harder than regeneration alone; the PDF and History name that speed in the user's unit), then the seconds without live speed from the `speed_missing` warning ("The 13 s without GPS speed: …"), then `speed_stats` and `phase_info.phase_pcts` gaps ("coasting" when the drive had neither a `deceleration` nor a `coast_down` phase; braking does not count as coasting) | Sentence; bullet list |
| What you feel (also in History) | `d.felt` (`reference`, `fallback`; the diagnosed source's row: `share`, `speed_min_kmh`/`speed_max_kmh`, `severity`, `workshop_mg`, `normal_mg`); fault and weak verdicts only | "This cause explains nearly all / most / about half / part of what the test measured at the trunk, nearest where you sit, at 80–120 km/h." plus whether a workshop acts on that level (GM's seat-track limit), that a trunk or tunnel is not the seat, "may not be what you feel" when the reference does not measure it, or that the run had no cabin or trunk sensor (see "What the driver feels" in `docs/metrics.md`) |
| Next step, fallback, cheap check | `d.order_code`, `d.source`, `d.zone`, `d.confidence_level` (Moderate adds the cheap check), `d.speed_dependence` (a done coast-down replaces the neutral check) | Fixed texts per order or source; a wheel fault on all four wheels gets the neutral coast check instead of an axle swap; a wheel/tire fault whose zone is not a wheel (cabin-only sensors, or fewer than two wheel sensors: "only the front-left wheel had a sensor") names no wheel and asks for a sensor at each wheel, and the axle swap is offered only for an axle zone; brakes name the front or rear brake discs and the cheap check is a few firm stops from about 100 km/h (steering wheel: front discs; seat and pedal: rear discs) |
| Check the fix | `d.order_code`, strongest `d.location_amplitudes[0].amplitude_mg` | Re-run instruction + today's level |
| Car diagram | `d.location_amplitudes` (ratio → dot size), `d.zone` | Corner, axle (wheel/tire: two corners of that axle near the top), engine bay, or centre tunnel; a sensor the order did not reach (0 mg) reads "-" |
| Drive-layout wording | `d.driveline_parts` (`front_drive`, `propshaft_rear`, likelier first), `d.conditions.drive_layout` / `propshaft` | A driveline fault's cause, next step and fallback name the gearbox output shaft, final-drive pinion and differential bearings (`front_drive` alone: the parts turning at wheel speed x final drive; never drive shafts or CV joints, which turn at wheel speed), the propshaft and its joints (`propshaft_rear`, today's wording), or both in order (AWD, where `front_drive` reads as the front propshaft and front differential pinion). A car without a propshaft (`propshaft` false) never reads "propshaft": P1/P2 are "per gearbox output-shaft turn", and the ruled-out line, empty worksheet and narrow-speed reason say "gearbox output shaft". Without a layout (`drive_layout` null or absent) the propshaft step gets "The car's drive layout was not given: on a front-wheel-drive car … the gearbox output shaft, the final-drive pinion and the differential bearings" appended |
| EV wording | `d.conditions.fuel_type` `EV` | The driveline source reads "Electric motor" (P1/P2 are once/twice per motor revolution), a driveline zone no axle dominates reads "the drive unit", the engine reads "not applicable", and the cheap check is a repeat drive instead of a neutral coast |

## Page 2 (workshop)

| Report element | Source | Format |
|---|---|---|
| Test conditions | `d.conditions` (speed source, RPM source, tire circumference, final drive and top gear with `tire_provenance` / `final_drive_provenance` / `gear_ratio_provenance`; `fuel_type` as the first "Powertrain" fact, which for an EV says the motor's electrical and gear-mesh orders are not analysed and replaces the final drive with "Reduction ratio" and drops top gear and engine RPM; `drive_layout` / `propshaft` as the "Drive layout" fact after it, "not provided; driveline advice assumes a propshaft to the rear axle" when unknown and absent for an EV without one; `final_drive_axle` appended to the final drive, e.g. `3.08 (entered by you), front axle`), `metadata.analysis_settings` tire size, `phase_info.phase_pcts`, `d.guided_phases` then `d.guided_phases_undetected` ("steady hold; tapped but not detected: speed sweep"), `sensor_locations`; without a speed range the "Driving covered" fact is left out, since every second is unknown speed | Facts grid; `3.15 (car library, model-family estimate)`, `not provided` for a missing reference; speed source as GPS, OBD, entered by hand, or entered by hand as the fallback; a live source that never gave a speed reads "GPS (no fix during the run)" / "OBD (no speed received)", taken from its `gps_unaligned` / `obd2_unaligned` rows (unknown slugs read "unknown") |
| Findings table | `d.order_findings[]` | `T1 - once per wheel turn`, `12.1 Hz @ 85 km/h`, km/h range, phases, presence %, location, level (the diagnosed row carries `d.confidence_level`, Weak when the coast-down contradicts it); a no-fault run lists no order found only faintly: the empty table then reads "Only a faint vibration at these orders was found, at a level a healthy car also has" |
| What the driver feels | `d.felt.causes[]` at `d.felt.reference` (fault and weak verdicts) | Source and orders, `level_mg` ("not measurable" at 0), share %, against workshop level, the limit (`12 mg (normal up to 2.0 mg)`), and a note with the limits' sources; without a reference only the fallback sentence |
| Amplitude per location | `d.location_amplitudes[]` | `250 mg (34 dB)`, ratio `1.0x`; "not detected" and ratio "-" when absent or 0 mg (the order did not reach that sensor) |
| Spectrum | `d.spectrum` (recurring peaks in mg over the moving samples, floor, order markers at the window speed; E1/E2 from the median measured RPM when RPM was measured) | Stems + dashed floor + order lines |
| Amplitude vs speed | `d.amplitude_vs_speed` | Lines per location; shown only for a ≥ 30 km/h sweep |
| Ruled out / not testable | `d.source_checks[]` | `Engine: not testable: no RPM or gear ratio`; `Engine: ruled out: the vibration kept going while coasting in neutral`; `Driveline: no match with the estimated final drive (car-library estimate); not conclusive`; `Engine: no match with the engine orders estimated for top gear; lower gears were not checked`; `Wheels/tires: not testable: the speed was entered by hand, …`; `Brakes: not testable: the drive did not brake firmly from speed`; `Wheels/tires: ruled out: the vibration at the wheel's rhythm came only while braking: …`; `faint_only`: "found only faintly, at a level a healthy car also has: not a cause" |
| Shop request | `d.verdict`, `d.source`, `d.order_code`, `d.driveline_parts` | Tire (residual balance under 5 g, 3 g preferred, in the balancer's fine mode; road force with GM's and Volvo's limits; match-mount; runout), brakes (disc runout on the hub, thickness variation, hub flange runout and caliper slides), driveline (per part, in `driveline_parts` order: gearbox output shaft, final-drive pinion and differential bearings for a car without a propshaft, front propshaft and front differential pinion for AWD; propshaft runout, working angles, rear differential pinion flange; without parts today's propshaft lines), engine, or other |

## Data quality (page 3 or footer)

| Report element | Source |
|---|---|
| Checks | `run_suitability[]` (`check_key` label, `state`, plain meaning; a warning keeps its measured specifics). Frame integrity warns on dropped frames, queue overflows or incomplete raw-replay coverage, so it never reads "no data lost" next to the replay-coverage warning; "Sensor mounting" is a warning row only when the loose-mount check found a loose sensor, named in the warnings below it |
| Warnings | `warnings[].code` → plain text, else the resolved `title` |
| Traceability | `run_id`, `sensor_model`, `firmware_version`, `raw_sample_rate_hz`, VibeSensor version |

## Units

- **Strength:** dB everywhere. In the diagnosis block, amplitude at the
  diagnosed order is in mg, always shown next to its dB above floor (see
  `docs/metrics.md`).
- **Frequency:** Hz, one decimal.
- **Speed:** integers in the user's speed unit setting (km/h, written km/u in
  Dutch, or m/s, as on the History page): every speed, the test-drive tips,
  the data-quality advice and the amplitude-vs-speed axis.
- **Format:** Dutch uses a decimal comma.
